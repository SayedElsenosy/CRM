# تحديث البوت إلى الأسئلة الديناميكية

هذه الحزمة المصححة تحل تعارضات الحزمة v2.2 السابقة. لا تنشر ملف v2.2 القديم: كان يكتب حالة غير موجودة في قيد جدول المتقدمين وعمودًا غير موجود في جدول الجلسات. البوت العامل في Supabase لم يتغير بمجرد تشغيل استعلام SQL خاطئ.

## الترتيب الصحيح

1. احتفظ بنسخة من ملفات البوت القديمة قبل أي نشر. لا تنقل مفاتيح الخدمة إلى ZIP.
2. في **Supabase → SQL Editor** على المشروع `gdapgkwpfprrvmbjsmls`، تأكد أن `003_dynamic_bot_flow.sql` نُفذ سابقًا، ثم شغّل محتوى `004_campaign_tracking.sql` وبعده `005_dynamic_flow_safety.sql`. ملف 005 يضيف الحالة اللازمة، ومفتاحًا ثابتًا لكل سؤال أساسي، وحماية للتكرار وسياسات قراءة للموظفين.
3. راجع ناتج الفحص الآتي في SQL Editor. يجب أن تكون سبعة أسئلة أساسية مفعلة ومفاتيحها مختلفة، وأول سؤال `age`، وآخر سؤال `license_document`:

```sql
select question_key, question_type, step_order, is_active, question_text
from public.bot_questions
order by step_order;
```

4. **افتح PowerShell أو Terminal في المجلد الذي يحتوي `package.json` ومجلد `supabase` بعد فك ZIP**. أمر `npx` لا يشتغل في SQL Editor. إذا لم يكن هذا المجلد مرتبطًا بالمشروع، نفّذ:

```powershell
npx supabase login
npx supabase link --project-ref gdapgkwpfprrvmbjsmls
```

ثم انشر:

```powershell
npx supabase functions deploy whatsapp-webhook --no-verify-jwt
```

إلغاء فحص JWT مطلوب لأن Meta يرسل webhook من دون JWT خاص بـSupabase؛ الدالة تتحقق من توقيع Meta باستخدام `META_APP_SECRET`. لا تُظهر هذا السر في PowerShell أو SQL.

5. جرّب من **رقم اختبار جديد** حتى يبدأ طلب جديد؛ الطلبات الجارية في الحالات القديمة تكمل مسارها السابق. اختبر: سن غير صالح، منطقة غير معروفة، إجابة «لا» على شرط أساسي، ثم طلب جديد مؤهل يصل للبطاقة والرخصة بصورتين تجريبيتين. راجع `bot_answers` و`applicant_sessions` و`documents` وظهور `READY_FOR_RECRUITER` في اللوحة.

## حدود النسخة

- تغيير نص السؤال وترتيبه من `bot_questions` ينعكس على الطلبات الجديدة والطلبات الديناميكية الجارية. `question_key` يحدد معنى السؤال الأساسي؛ لا تغيّره أو توقف الأسئلة الأساسية السبعة. السن يجب أن يظل أولًا، والمستندات بعد الفرز، والرخصة آخر سؤال.
- يمكن إضافة سؤال نصي اختياري جديد من قاعدة البيانات، لكن شروط الأهلية الأساسية (السن ١٨–٤٥، المناطق، الموتوسيكل، الرخصة، الوردية) ما زالت قواعد تحقق داخل الكود.
- `ad_id` يُملأ فقط لو أرسل Meta معلومة إحالة إعلان. `campaign_id` سيبقى فارغًا ما لم نربط معرف الإعلان ببيانات حملات Meta لاحقًا. لا تستنتج `campaign_id` من رسالة واتساب.
- لا توجد صفحة إدارة الأسئلة أو المستخدمين في لوحة التحكم بعد. هذه حزمة تحديث الـWebhook والقاعدة فقط.
- الـWebhook يرد على Meta قبل انتهاء المعالجة في الخلفية. لو فشلت المعالجة بعد الإقرار، قد يحتاج الطلب تدخلًا يدويًا؛ النسخة لا توفر قائمة إعادة محاولات دائمة.
